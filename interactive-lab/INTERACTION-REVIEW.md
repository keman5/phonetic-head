# 交互审查与修复

本次审查保留工作区已有的模型、音标、字母、教师工具及未提交改动。新增课程界面复用项目配色、`lab-select` 和播放控制，不引入组件库。

| 发现 | 本次处理 |
| --- | --- |
| 只有音标和字母名称入口，学习者不知道如何把发音用进真实语言。 | 新增教学系列及声音 → 单词 → 短语 → 句子四阶段；允许逐步前进或直接切换。 |
| 字母名称和单词中的发音容易混淆。 | 系列旁明确说明字母名称 `/diː/` 与目标音 `/d/`。 |
| 朗读时缺少文字跟随，不能知道当前读到哪里。 | 课程正文支持逐词高亮，以背景和下划线同时标识；具体时序由音频控制器提供。 |
| 单独发音没有语义和自然朗读提示。 | 每一步展示英文、音标、中文释义和练习提示。 |
| 阶段切换后容易丢失键盘焦点。 | 标准 tablist/tabpanel、游走焦点及方向键/Home/End，更新内容时保持阶段焦点。 |
| 长句和多按钮在窄屏容易挤压。 | 词语自动折行；手机上主播放按钮和学习模式选择器独占一行；课程操作触控区域至少 44px。 |

验证入口：`node --test curriculum-ui.test.mjs`，使用已启动的本机 4173 服务和已安装 Chrome/Edge。覆盖四阶段、字母名称区分、键盘焦点、朗读高亮清理、系列切换、320–1440px 布局和切回音标模式。已在本机 Chrome 运行通过，并查看 `qa/curriculum-desktop.png` 和 `qa/curriculum-mobile.png` 的真实模型与课程界面。

边界：跟读是练习引导，不进行自动发音评分。逐词高亮精度及连续口型准确性由音频与模型实现决定，不能仅靠界面验证。
